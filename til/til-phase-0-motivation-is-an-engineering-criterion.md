# TIL — Phase 0: motivation is an engineering criterion

When a project runs on ~6–10 free hours a week, the single biggest risk
isn't a hard algorithm — it's **abandonment**. So "which domain will
still make me want to open the laptop in week 11?" stops being a taste
question and becomes an engineering one, weighted alongside feasibility
and measurability.

That reframing is what moved this project from a "serious-sounding"
corporate-ownership graph to the **Magic: The Gathering rules** corpus.
Magic wins on three technical grounds, not just enthusiasm:

1. **A judge-curated golden set already exists** (RulesGuru). I get to be
   the *curator* of the answer key, not its author — which dissolves the
   "I'm not enough of an expert to validate this" risk.
2. **The Comprehensive Rules are genuinely hard text**: hierarchical
   numbering (601.2b), cross-references, exceptions that override general
   rules, quarterly updates. A legitimate proxy for dense regulatory text.
3. **The answer is objective.** Rules questions have a right answer.

And because motivation is a risk, I hedged it like one: four contingency
gates (G1 licensing, G2 golden set, G3 extraction, G4 last resort), each
with a pre-registered exit plan (down to "switch to the D&D 5e SRD, which
is Creative Commons"). Failing a gate doesn't kill the project — it
triggers the plan I already wrote. The scaffold is domain-agnostic on
purpose, so the exit costs no infrastructure work.

The transferable lesson: **treat your own follow-through as a system
input.** Pick the domain that keeps you engaged *and* lets you measure
the truth — then protect the choice with gates.
